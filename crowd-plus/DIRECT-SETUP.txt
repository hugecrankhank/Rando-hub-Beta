CROWD CONTROL+  -  THE DIRECT CONNECTION
Crowd Control+ joins your TikTok LIVE itself. No TikFinity, no browser
window, no key.
=========================================================================

WHAT "DIRECT" IS
----------------
Crowd Control+ has three ways to hear your TikTok LIVE:

  Direct (default)      The bridge joins your LIVE itself, with the
                        tiktok-live-connector library. Nothing else to
                        run or log in to. Type your name, Connect.
  TikFinity             The free TikFinity app connects to TikTok; the
                        bridge listens to it. The backup.
  Local signer          The bridge opens your own LIVE page in a Chrome /
                        Edge window and reads what TikTok shows there.

Direct is the "own bridge" approach: the same library, the same connect-
by-username idea, inside Crowd Control+ so the gifts go straight to
your effects, alerts, goals and overlays. Everything happens on the PC
you stream from.

HOW IT WORKS WITHOUT A KEY
--------------------------
TikTok only accepts LIVE connections whose requests are signed. The
library doesn't sign them itself; it asks Euler Stream's "sign server"
to, once per connection. Euler Stream does that for free with no key,
within a limit shared by everyone who has no key. One streamer
connecting once per stream is well inside it.

A key is optional. A free one (Community plan at
https://www.eulerstream.com) gives you a limit of your own, so a busy
evening for everyone else can't make you wait. If the free shared
server is busy, the bridge says so and tries again in 3 minutes; the
rest of Crowd Control+ keeps running.

Can Crowd Control+ get a key for you? No: a key is tied to an Euler
Stream account, which means signing up on their site, and it stays the
same afterwards, so it's a paste-once thing, not a per-stream thing.
And it isn't needed.


STEP 1. Start Crowd Control+
  Double-click "Start Crowd Control+.bat" (Mac: the .command file).
  The first time, it installs the library (tiktok-live-connector) into
  node_modules: about a minute, needs internet. Then the control panel
  opens at http://localhost:21214/studio

STEP 2. Connect
  On the Dashboard, in "TikTok connection":
  - Leave it on "Direct (recommended)".
  - Type your TikTok name (without @).
  - Click Connect.
  Your name is saved in mapping.json ("username"), so next time you
  only click Connect (it connects by itself at startup anyway).

  Not live yet? The dot stays red and the status says "Waiting for
  TikTok LIVE"; the bridge retries every minute until you're live, then
  shows "Live as @yourname" (green).

STEP 3. The rest is the same as always
  Connect the game (⋯ → Crowd effects → on, ws://localhost:21214), add
  the overlays to OBS or TikTok LIVE Studio. See INSTRUCTIONS.txt Part
  1, steps 5 and 6.

OPTIONAL. A key of your own
  1. Go to https://www.eulerstream.com and sign up.
  2. Pick the Community plan (free).
  3. In your account, create an API key and copy it. Keep it private:
     it's tied to your account.
  4. Paste it into "Euler Stream key (optional)" on the Dashboard and
     click Connect. It's saved in mapping.json ("signApiKey").
  With a key the bridge retries every 30 seconds instead of every
  minute.


EVERY STREAM
------------
  Start Crowd Control+, go LIVE, open Rando Hub. Direct reconnects by
  itself. No TikFinity to open, no LIVE window to keep.


IF YOU'D RATHER EDIT mapping.json
---------------------------------
  "source": "direct",
  "username": "yourname"
  and, only if you have one:
  "signApiKey": "your_key"
  "signServer" can be "euler" (default), "tiktools" (api.tik.tools,
  7-day trial, key required) or any https:// sign-server address.


WHEN SOMETHING'S WRONG
----------------------
"Direct: library not installed yet"
  The first-time setup didn't run (no internet, or you started with
  "node bridge.mjs" by hand). Crowd Control+ uses TikFinity for that
  run. Start it again from "Start Crowd Control+.bat", or run
  npm install in this folder.

"Sign server busy (free, no key), retrying"
  Everyone without a key shares one limit and it's full right now. The
  bridge waits 3 minutes and tries again. For a limit of your own, add
  the optional key (above). Or switch to TikFinity meanwhile.

"Sign server refused, retrying"
  With a key: the key is wrong, or the plan's limit for the day is used
  up; check it on eulerstream.com. Without one: Euler Stream may have
  changed its free terms; add a key, or switch to TikFinity or the
  local signer (they don't use the sign server).

"couldn't join @name's LIVE ... Are you live?"
  You aren't live yet (normal: it keeps retrying), the name is wrong
  (no @, no spaces), or TikTok changed something and the library needs
  an update: run   npm update tiktok-live-connector   in the folder.
  TikFinity is the backup until then.

Gifts arrive but a streak counts once
  Correct: a gift sent 10 times in a row arrives as one gift with
  count 10 when the streak ends (TikTok reports it that way), and the
  effect runs with that count.

Switching sources
  Pick another source on the Dashboard and Connect; Direct's
  connection is closed. Your gift setup, overlays and stats are the
  same for all three.


THE STANDALONE rando-tiktok-bridge (server.js) YOU WROTE
---------------------------------------------------------
It does the first half of Direct: tiktok-live-connector by username,
events re-sent on a WebSocket. To use it with Rando Hub it would also
need the bridge's side: the game expects Crowd Control+'s messages
(effects by id, durations, the effect list it sends when it connects),
the gift-to-effect mapping, streak handling for every gift type,
follows / shares / superfans, reconnecting, and the control panel and
overlays. All of that is already in Crowd Control+'s Direct source, so
the shortest path is the steps above. The pieces of yours that carry
over as-is are the username connect and the repeatEnd check, which
Direct does the same way.
